# Backend MVP не включает UI и обучение ML; интеграция через порты

Контекст: команда хакатона разделена на фронт/бэк/ML, но код фронтенда и ML-модели пока не существует в этой репе и не будет объединён с бэкендом за 7 дней до дедлайна (тиммейты пишут их параллельно и асинхронно). Обязательность платформы INDASTRICS как среды исполнения не подтверждена организаторами.

Решение: backend реализует только свою зону из `BACKEND_TZ_FOR_TEAM.md` §1 — REST API по контракту фронтенда, схему БД, RBAC, эмуляцию внешних источников и пакет для сдачи. UI не строится вообще — Swagger/OpenAPI является единственной демонстрацией контракта для фронтенд-команды. ML-модель не обучается и не демонстрируется как часть бэкенда — вместо неё вводится ML Prediction Port; Stub Predictor реализует этот порт только для внутренних тестов бэкенда, не для защиты проекта. Архитектура остаётся независимой от INDASTRICS, но с адаптерными швами (портами), позволяющими без переписывания API подключить: (а) реальную ML-модель через тот же порт, (б) INDASTRICS как одну из реализаций порта, если позже подтвердится обязательность, (в) реальный фронтенд без изменений контракта.

Почему: 7 дней не позволяют одной команде параллельно закрывать три зоны ответственности; границы уже зафиксированы собственными документами команды; ожидание ответа организаторов по INDASTRICS стоило бы времени, которого нет.
