# Ограничения и честные упрощения MVP

Разбросаны по комментариям кода и ADR — здесь собраны в одном месте, чтобы эксперту не приходилось искать их по репозиторию. Каждый пункт — осознанное решение под сжатый срок разработки, не забытая недоделка.

## Данные

- **Операционное окно, не архив** (`docs/adr/0004`): в БД загружен только `журнал_событий_пример.csv` (169 993 строки, август 2026). Полные `ext-journal-*.csv` (313 млн строк, 2019-2026) сознательно не читаются вообще — оценивается работающий дашборд и правдоподобие эмуляции, не способность обслуживать произвольные многолетние запросы.
- **Реальных координат объектов нет и не будет** (подтверждено организаторами) — `Location` в ответах `/facilities` детерминированная (стабильная на facility_id), но не географически настоящая; помечена `is_demo: true`.
- **Схематичная геометрия планировки** (`/facilities/{id}/layout`) — GeoJSON корректной формы, но не настоящий план объекта.

## Эмуляция

- **StubPredictor не обучен** — детерминированная функция от реального количества alarm/anomaly показаний, а не ML-модель. Существует только для внутреннего тестирования backend-контракта и явно помечен как временный (`CONTEXT.md`, термин «Stub Predictor»).
- **`priority_score`** — `probability*70 + urgency*30`, где `urgency` растёт по мере приближения SLA. Формула не регламентирована фронтенд-контрактом (явно оставлено на усмотрение команды), это MVP-базовая линия, не финальный алгоритм ранжирования.
- **`data_health`/freshness-бакеты** — эвристика по возрасту данных относительно `FRESHNESS_BOUNDARIES` (5/15/60 минут), не результат мониторинга реальной инфраструктуры.

## Идентификаторы и конкурентность

- **`display_number` заявки** (`ЗН-{год}-{порядковый}`) — порядковый номер вычисляется как `count(*) за год + 1` в той же транзакции, не атомарная последовательность БД. Безопасно для однопользовательского демо/теста, не защищено от гонки при реальной параллельной записи.
- **`WorkOrder.version`** присутствует в контракте ответа, но пока ничем не инкрементируется — на данный момент нет PATCH/transition-эндпоинта, который бы его использовал (только оптимистичная конкурентность у `Risk`).

## Жизненный цикл заявок

- **Статусы `cancelled`/`integration_error` недостижимы автоматически** — автопродвижение (`draft → ready → assigned → in_progress → completed`) идёт по времени от создания. `cancelled` — осознанное решение человека (не эмулируется), `integration_error` возможен только при реальном сбое интеграции с внешней системой, которой не существует. Оба остаются в контракте ради полноты enum, но эндпоинта, который бы их проставлял, пока нет.
- **Право на создание** — `work_order.create_draft` ИЛИ `work_order.submit`; в каталоге permissions нет отдельного разграничения "создать" vs "отправить", т.к. реальной отправки во внешнюю систему нет и не будет.

## RBAC

- **LDAP/AD только mock** — реальный каталог Active Directory заказчика подтверждён организаторами, но тестового контура на хакатоне нет.
- **Два демо-пользователя** (`manager`/`dispatcher`) — не полноценная система управления пользователями, только для демонстрации capability+scope модели.

## ML Prediction Port

- **Формат карточки прогноза не регламентирован** фронтенд-контрактом — `top_factors`/`recommendation` собраны по собственной, задокументированной, но не согласованной с data science схеме (лёгкая замена при реальной интеграции, т.к. порт — HTTP-граница, см. `docs/adr/0006`).
