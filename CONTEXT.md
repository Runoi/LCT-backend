# Backend Москоллектор

Сервис предиктивной аналитики для прогнозирования инцидентов и отказов датчиков инженерных коллекторов Москвы. Хакатон-MVP, не промышленное внедрение. Этот файл описывает домен и границы именно **backend-части**, которая в этой репе разрабатывается отдельно от фронтенда и ML-модели.

## Language

**MVP (в этом репозитории)**:
Объём работы бэкенда, полностью описанный P0-чеклистом (схема БД, потоковый ETL, эмуляция внешних источников, `/api/v1/*` по контракту фронтенда, RBAC, интерфейс приёма прогноза, пакет для сдачи). Не включает UI и не включает обучение/выбор ML-модели — это отдельные зоны ответственности других частей команды.
_Avoid_: «MVP» в значении «весь хакатонный проект целиком» (фронт + бэк + ML) — для этого смысла нужно явно говорить «MVP всего проекта».

**ML Prediction Port**:
Контракт, через который бэкенд получает прогноз от ML-части: вход — идентификатор канала/объекта + временной срез признаков; выход — `probability`, `prediction_window`, `risk_level`, `top_factors[]`, `recommendation`. Бэкенд не содержит логики прогнозирования, только потребляет результат через этот порт.
_Avoid_: «ML-модуль» как часть бэкенда — модель тренируется и подбирается отдельной командой, бэкенд лишь определяет и вызывает контракт.

**Stub Predictor**:
Временная реализация ML Prediction Port, возвращающая правдоподобные, но не обученные предсказания. Существует только для внутреннего тестирования backend-контракта (`/api/v1/risks` и далее) и исчезает при подключении реальной модели.
_Avoid_: «мок ML» без уточнения — легко спутать с эмуляцией внешних источников, у которой противоположный жизненный цикл.

**Capability + scope модель**:
Модель прав доступа без фиксированных ролей: пользователю выдаётся набор permission-строк (`facility.read.all`, `risk.acknowledge`, ...) плюс `scope` — объект, описывающий, на какие `facility_ids` эти права распространяются (`all_facilities`, `assigned_facilities: [...]`, либо группа по «району»). Роль — это просто именованный пресет permissions+scope, не отдельная сущность в правах.
_Avoid_: жёстко зашитые роли (`role === 'manager'`) в коде проверки доступа — вся фильтрация обязана идти через permissions+scope, а не через имя роли.

**Район (scope-уровень)**:
Промежуточный уровень группировки объектов между «один объект» и «все объекты города», нужный для будущей роли «Диспетчер района» из реальной модели заказчика. Реализуется как список `facility_ids`, привязанный к `scope`, а не как отдельная сущность в дереве объектов.
_Avoid_: путать с уровнями иерархии объекта (здание/коллектор/участок) — это ось прав доступа, а не структура самого объекта.

**Эмуляция внешних источников**:
Обязательный, оцениваемый экспертами постоянный компонент архитектуры, имитирующий СМВУ/ОДС/реестр оборудования/систему заявок правдоподобными данными на основе паттернов реального датасета (не случайным шумом). В отличие от Stub Predictor — часть финальной сдачи, а не временная затычка на время разработки.
_Avoid_: путать со Stub Predictor — разная роль (постоянный демонстрируемый компонент vs временный тестовый костыль) и разный жизненный цикл.
